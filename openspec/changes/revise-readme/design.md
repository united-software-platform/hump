## Context

Текущий `README.md` — один файл на 11 КБ: восемь разделов, из которых четыре первых объясняют
замысел, а инструкция начинается с раздела «Запуск шлюза». Мотивация переработки — в `proposal.md`
(раздел «Why»).

Факты, которые ограничивают текст и проверены на работающем окружении:

- шлюз поднят, `/health/liveliness` и `/ui/` отвечают `200`;
- `/health/readiness` возвращает `{"status": "healthy", "db": "Not connected"}`;
- страница входа панели называет учётные данные по умолчанию: `admin` и значение
  `LITELLM_MASTER_KEY`, но попытка входа завершается `Authentication Error, Not connected to DB!`;
- `.env` и `.env.claude` от агента скрыты намеренно, поэтому их содержимое в текст не попадает —
  источником состава переменных служат `.env.example` и `.env.claude.example`.

Правила репозитория, действующие на этот файл: `README.md` не ведёт таблицу версий
([DOC-022](../../../rules/documentation-rules.md#жизненный-цикл-документа)), абсолютные ссылки
допустимы только там, где цель действительно внешняя
([DOC-015](../../../rules/documentation-rules.md#ссылки-doc-015)), HTML запрещён
([DOC-005](../../../rules/documentation-rules.md#разметка-markdown)), заголовки идут без пропусков
уровней, файл начинается с заголовка, назначения и навигации
([DOC-014](../../../rules/documentation-rules.md#структура-файла)).

## Goals / Non-Goals

**Goals:**

- Читатель, впервые открывший репозиторий, доходит от клонирования до отвечающего шлюза, не выходя
  за пределы `README.md`.
- Состав и назначение переменных окружения видны в одном месте, без чтения примеров и compose-файлов.
- Утверждения README проверяемы: каждая команда и каждый адрес соответствуют текущему состоянию
  `Makefile`, `docker-compose.hump.yml` и `config/litellm.yaml`.
- Ограничения названы явно, а не умолчаны — в первую очередь недоступность входа в панель.

**Non-Goals:**

- Не вводится отдельный документ об архитектуре: содержание остаётся в одном файле.
- Не описывается внутреннее устройство LiteLLM и Ollama — README отсылает к их документации.
- Не документируется ничего, чего нет в репозитории: будущая логика маршрутизации упоминается только
  в разделе «Статус».

## Decisions

### Решение 1. Инструкция выше повествования, повествование сохраняется

Порядок разделов: назначение → предусловия → развёртывание → настройка → запуск → обращение к API
→ панель → проверка → эксплуатация → о проекте (название, проблема, цель, задачи) → состав → статус.

Альтернативы: оставить текущий порядок (отвергнуто — инструкция остаётся на пятом экране);
вынести повествование в `docs/about.md` (отвергнуто — README перестаёт объяснять, зачем проект
существует, а `DOC-011` требует выноса для объёмных тем, тогда как здесь это около сорока строк).

Повествовательная часть сжимается, но не удаляется: объяснение метафоры «сортировочная горка»
и связка «проблема — цель — задачи» отвечают на вопрос «зачем проект», а без них README превращается
в инструкцию к чужому инструменту.

### Решение 2. Переменные окружения — таблицей в README, комментарии в примерах сокращаются

В README две таблицы (шлюз и агент) со столбцами: переменная, назначение, обязательность,
умолчание или пример. В `.env.example` у каждой переменной блока `LiteLLM gateway` остаётся
однострочный комментарий назначения; многострочные пояснения, дублирующие таблицу, переезжают
в README.

Альтернатива — только ссылка на `.env.example` (отвергнута пользователем): состав переменных
пришлось бы собирать в другом файле, а обязательность и умолчания в комментариях не видны.

Риск дублирования принимается осознанно и ограничивается: значения и умолчания живут в примерах
и compose-файлах, таблица называет имя, смысл и обязательность.

### Решение 3. Панель описывается вместе с её ограничением

Раздел о панели называет адрес `http://localhost:4000/ui`, учётные данные по умолчанию и то, что
вход сейчас не проходит: шлюз работает без базы данных, поэтому авторизация возвращает
`Authentication Error, Not connected to DB!`. Рядом — отсылка к изменению `enable-litellm-ui`.

Альтернативы: не упоминать панель (отвергнуто — читатель находит `/ui` сам и тратит время
на выяснение); описать панель как рабочую (отвергнуто — утверждение ложно и проверяется первым же
входом).

### Решение 4. Предусловия и развёртывание описываются от чистого клона

Раздел развёртывания начинается с `make init`, продолжается заполнением `.env` и завершается
`make hump-up`. Явно указывается, что `make init` создаёт `.env` и `.env.claude` из примеров
и существующие файлы не перезаписывает, а часть шагов (SSH-ключ, профиль агента) относится
к окружению разработки и к запуску шлюза не обязательна.

Альтернатива — описывать только `make hump-up` (отвергнуто: без `.env` цель поднимает шлюз
с пустым мастер-ключом, и сбой проявляется позже, при первом запросе).

### Решение 5. Примеры запросов даются через оба маршрута

В разделе обращения к API — пример `POST /v1/chat/completions` с `hump-local` и указание, что для
облачного маршрута меняется только имя модели на `hump-cloud`. Ключ в примере — плейсхолдер `sk-...`.

## Risks / Trade-offs

- **Таблица переменных расходится с `.env.example` при будущих правках** → таблица называет имя,
  назначение и обязательность, но не значения; значения остаются единственным экземпляром
  в примерах. В задачи включена сверка обоих файлов.
- **Раздел о панели устаревает сразу после применения `enable-litellm-ui`** → в разделе стоит явная
  отсылка к этому изменению, а в задачах `enable-litellm-ui` — пункт переписать раздел.
- **README растёт в объёме** → повествовательная часть сокращается примерно вдвое, разделы держатся
  короткими по `DOC-009`, объёмные пояснения (host-runner, устройство проверки) остаются ссылками
  на соответствующие файлы.
- **Проверить команды из контейнера агента нельзя: Docker'а в нём нет** → команды сверяются
  с рецептами `Makefile` и белым списком host-runner'а, а фактический прогон `make hump-up`
  и `make hump-check` выполняется на хосте пользователем.

## Migration Plan

Отдельного развёртывания не требуется: изменение затрагивает только `README.md` и комментарии
в `.env.example`. Откат — возврат предыдущей версии файлов.
