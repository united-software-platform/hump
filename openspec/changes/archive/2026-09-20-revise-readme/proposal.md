## Why

README проекта отвечает на вопрос «зачем нужен Hump», но почти не отвечает на вопрос «как им
пользоваться». Развёртывание с нуля не описано вовсе: про `make init`, создание `.env` и `.env.claude`
в файле нет ни строки, хотя без этого шага запуск невозможен. Состав переменных окружения читателю
приходится собирать по тексту и по комментариям `.env.example`, обязательность и умолчания нигде
не сведены. Вход в панель LiteLLM не описан, а как именно обратиться к шлюзу запросом — показано
только в виде проверочного скрипта. При этом первые четыре экрана заняты метафорой, проблемой, целью
и задачами: человек, открывший репозиторий, чтобы поднять шлюз, доходит до инструкции последним.

## What Changes

- **Порядок разделов переворачивается под использование.** Сверху — назначение проекта на 3–5 строк
  и предусловия, затем развёртывание, настройка, запуск, обращение к API, панель, проверка
  и эксплуатация. Повествовательная часть — объяснение названия, проблема, цель, задачи — сохраняется,
  но сжимается и переносится под инструкцию.
- **Добавляется раздел развёртывания с нуля.** Последовательность `make init` → заполнение `.env`
  → `make hump-up`, с указанием, что `make init` создаёт `.env` и `.env.claude` из примеров и не
  перезаписывает существующие файлы.
- **Добавляется таблица переменных окружения**: имя, назначение,
  обязательность, умолчание или пример. Отдельно переменные шлюза (`.env`) и переменные агента
  (`.env.claude`); причина разделения файлов остаётся в тексте.
- **Добавляется раздел об обращении к API** с примером запроса к `hump-local` и `hump-cloud`:
  сейчас единственный пример вызова спрятан внутрь описания проверки.
- **Разделы о панели и данных шлюза встраиваются в новую структуру.** Изменение
  `enable-litellm-ui` было применено раньше этого и уже добавило их в README — но дописало в конец
  прежней структуры. Здесь они занимают своё место в порядке использования. Ограничение «вход без
  базы не проходит», которое предполагалось зафиксировать при планировании, снято тем изменением:
  панель работает, и README описывает её как рабочую.
- **Комментарии `.env.example` приводятся в соответствие с таблицей**: каждая переменная блока
  `LiteLLM gateway` получает однострочное назначение. Значения переменных не меняются.
- **Раздел «Статус» сохраняется** и дополняется положением дел с панелью.

Не входит в изменение: включение панели (Postgres, `DATABASE_URL`, учётные данные UI) — отдельное
изменение `enable-litellm-ui`; правки `docker-compose.hump.yml`, `Makefile` и `config/litellm.yaml`.

## Capabilities

### New Capabilities

Нет: изменение не вводит нового поведения системы.

### Modified Capabilities

Нет: требования `llm-gateway` не меняются — правится только описание уже существующего поведения.
Change помечен `skip_specs: true` в `.openspec.yaml`.

## Impact

- `README.md` — переработка структуры и содержания.
- `.env.example` — комментарии к переменным блока `LiteLLM gateway`.
- Источники фактов для сверки: `docker-compose.hump.yml`, `config/litellm.yaml`, `Makefile`
  (цели `init*`, `hump-*`), `tools/litellm/check.sh`, `.env.example`, `.env.claude.example`.
- Ограничения README подчиняются правилам репозитория: [DOC-015](../../../rules/documentation-rules.md#ссылки-doc-015)
  разрешает абсолютные ссылки в `README.md` только там, где цель действительно внешняя,
  [DOC-022](../../../rules/documentation-rules.md#жизненный-цикл-документа) освобождает `README.md`
  от таблицы версий.
- Связанное изменение: `enable-litellm-ui` — снимает ограничение панели, после его применения раздел
  о панели в README переписывается.
