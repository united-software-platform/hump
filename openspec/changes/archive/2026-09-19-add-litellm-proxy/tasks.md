## 2. Проверка работоспособности

- [x] 2.1 Создать `tools/litellm/check.sh` на `wget`: проверяет `GET /health/liveliness`
      и `GET /health/readiness` без авторизации, затем `GET /health` с мастер-ключом, затем
      по одному `POST /v1/chat/completions` на локальный и облачный маршрут; скрипт печатает
      результат по каждому шагу и завершается кодом `1`, если хотя бы один настроенный маршрут
      не ответил, `0` — если ответили все

      (`http://host.docker.internal:<порт>`); убедиться, что `sh tools/litellm/check.sh` на
      незапущенном сервисе завершается ненулевым кодом с внятным сообщением, а не трассировкой

## 5. Ollama в составе окружения и управление через host-runner

Группа добавлена по ходу реализации: исходный план полагался на Ollama, установленный
пользователем на хосте, и на ручной запуск сервисов — оба допущения не подтвердились
на живом окружении.

- [x] 5.1 Добавить в `docker-compose.hump.yml` сервис `ollama` с именованным томом под веса
      и разовый сервис `ollama-pull`, загружающий модель; порт наружу не публиковать — проверить,
      что шлюз обращается к нему по внутренней сети (`http://ollama:11434`)
- [x] 5.2 Задать `OLLAMA_API_BASE` умолчанием на уровне compose: без значения LiteLLM молча берёт
      `localhost:11434` и отказ выглядит беспричинным; проверить по выводу `hump-check`, что
      в ошибке маршрута фигурирует именно настроенный адрес
- [x] 5.3 Добавить цели `hump-up`, `hump-down`, `hump-logs`, `hump-check` в `Makefile` и в белый
      список `tools/host-runner/runner.py`; убедиться, что после перезапуска раннера цели видны
      в его перечне и выполняются. Цель `hump-check` читает `.env` на хосте — мастер-ключ
      не попадает в окружение агента
- [x] 5.4 Согласовать имя модели в `config/litellm.yaml` и в команде `ollama-pull`: значения
      совпадают, в обоих файлах стоит перекрёстный комментарий
- [x] 5.5 Отменить умолчание, заданное в 5.2: убрать блок `environment:` из
      `docker-compose.hump.yml` и оставить адрес единственным источником — `.env` через `env_file`.
      Основание: подстановка `${OLLAMA_API_BASE:-...}` берёт значение сначала из окружения
      процесса, запустившего compose, и переменная, оставшаяся в окружении host-runner'а
      от прежней редакции `.env`, молча перекрыла верное значение — шлюз ходил
      на `host.docker.internal:11434` при верно настроенных `.env`, `.env.example`
      и `config/litellm.yaml`. Проверить прогоном `hump-check` после пересоздания сервисов;
      потерю умолчания зафиксировать в `design.md` — раздел «Адрес Ollama — только через
      `env_file`» и пункт в «Risks / Trade-offs»
